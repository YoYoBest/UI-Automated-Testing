# 运行时模块发现

## 事实来源

按以下顺序读取现有实现，不复制项目布局、接口路径或树转换逻辑：

- `src/ei_ui_smoke/project_layout.py`：解析 parent/view 布局、读取 `VITE_APP_ID`、发现详情前缀。
- `src/ei_ui_smoke/module_index.py`：源码页面索引、运行时菜单转换、详情节点挂载、搜索。
- `src/ei_ui_smoke/menu_capture.py`：登录、主权限菜单和详情权限树抓取。
- `src/ei_ui_smoke/urls.py`：从登录地址或业务地址构造模块 URL。
- `src/ei_ui_smoke/launcher.py`：展示、搜索、多选、父节点展开和执行目标解析。

## 发现流程

1. 用 `resolve_view_root()` 解析用户选择的目录；同时接受 `ei-parent`、`fi-parent`、`ei-view`、`fi-view`，不要写死项目名。
2. 用 `discover_modules()` 生成源码技术索引。该结果只说明源码中存在候选页面，不能证明当前用户有权限，也不能提供可靠的中文菜单和运行路由。
3. 从目标 view 的 `.env` 读取 `VITE_APP_ID`。不要把 EI/FI 的应用 ID 固化在 Skill 或新增分支中。
   当自动化必须直接调用页面已有的只读接口时，也读取同一文件的 `VITE_APP_BASE_API`，将接口相对路径附加到该代理基址；不得假定 API 位于部署域名根路径。
4. 用户提供已部署系统地址并登录后，通过 `capture_menu()` 监听成功的 `/funcPerm/getUserFuncPerm` 响应。
   动态审批流程只需以可见浏览器采集经办人 `maker` 的独立 state；后续处理人由流程预览返回的唯一 `loginName` 决定，并使用 `EI_WORKFLOW_LOGIN_PASSWORD` 自动登录、以摘要命名的账号级 state 缓存复用。不得复制普通 `auth-state.json` 冒充处理人，也不得把 Cookie、Token、state 内容、用户名或密码写进配置。无头模式没有有效经办人 state 时必须在打开流程前失败；菜单等待超时需仅报告脱敏 URL、登录页可见性和有限候选响应。
5. 复用主菜单请求中的认证请求头获取详情权限树和按钮权限。至少保留 `Authorization`、`x-access-token`、`token` 和 `x-tenant-id` 中实际存在的头；不要假定 `context.request` 自动继承页面请求的全部认证头或租户上下文。
6. 用 `modules_from_menu()` 保留 `meta.title`、`children`、`funcCode`、`path`、`component`，生成当前用户可见的真实层级和路由。
7. 从源码发现详情前缀，再请求 `getUserFuncPermTreeByFuncCode`；递归保留响应中每一层 `children`，把完整详情树挂到对应业务模块。不要只支持已知的 `ZGJJ_`、`CGJJ_`、`JJGL_`，FI 等项目可能使用其他字面量前缀。
   还要扫描静态 `getUserFuncPermTree({ fatherId: "..." })` 调用：以调用 Vue 文件的相对组件路径和 `fatherId` 形成请求，复用菜单认证头向源码声明的只读权限树接口请求。父 ID 树独立保存在 `_detailFatherTrees`，不得混入前缀树或逐页打开 DOM。
8. 获取主菜单后复用认证头请求当前用户按钮权限接口；EI 项目使用 `/ei-service/proj/getUserButtonPermissions?appId=...`，从 `data.funcPerm[].code` 提取权限码。入口组件负责提供“按钮文字 + `$hasButton('权限码')`”映射，权限接口负责过滤当前用户可见按钮。不要逐页打开路由核对 DOM。

请求附加接口时保留主菜单请求中的 `Authorization` 和租户头（如 `x-tenant-id`），并沿用部署系统的代理前缀。不要只复制 token 而遗漏租户，也不要把源码中的相对 API 路径直接拼到域名根路径。

进入 `capture_menu()` 的菜单等待前，必须具备至少一种可执行认证路径：有效 storage state、可用凭证，或明确的人工登录流程。菜单等待超时时记录当前 URL、登录表单是否仍可见、已观察到的候选菜单请求和响应状态；面向用户的结论要区分“缺少凭证”“认证状态过期”“应用地址错误”“存在验证码/二次验证”和“菜单接口路径已变化”，禁止只返回原始的 Playwright `Timeout 60000ms`。

## 树与选择规则

- 保留运行时 `children` 父子关系，不用 DOM 侧边栏文字重新拼树。
- 先原样建立主菜单层级，再解析每个节点的源码身份，最后把操作和详情挂到已确认 owner；禁止为了界面更简洁按中文名称合并、提级、降级或重排节点。截图只用于验证转换结果是否符合真实系统，不能替代接口 `children`、菜单 ID、组件和路由关系。
- `ALL` 代表全部可运行模块，不代表所有纯目录节点。
- 选中父节点时始终收集其全部可运行后代；父节点自身可运行时也加入执行目标，纯目录节点则只执行后代。父子同时被选中时按模块 ID 去重后再执行。
- 父节点通过鼠标选中时，同步高亮当前树中的全部子孙节点；取消父节点时同步取消其子孙节点，让视觉选中范围与实际执行范围一致。状态数量仍按可执行模块 ID 去重统计。
- Parent selection only performs this tree-level cascade. Build the execution plan from the executable nodes that remain selected after all user changes; never re-expand a selected parent path while resolving targets. A child branch manually deselected after a parent cascade, including all of that branch's descendants, is an explicit exclusion and must not run.
- `requires_business_id=True` 的详情节点必须先取得业务记录 ID，不能当普通列表入口直接运行。
- 搜索命中子节点时保留并展开祖先路径。
- 普通菜单一级、二级默认展开，三级及以下默认收缩；搜索结果全部展开。
- 详情树沿用相同的默认层级规则：一级、二级展开，三级及以下收缩；搜索时再展开匹配路径。
- 不因父节点自身也是一个详情节点而停止递归；例如必须完整保留并展示 `建设项目 / 详情 / 投前管理 / 项目立项|项目决策|重大调整`。
- 运行时菜单出现连续同名父子节点时保留两层，因为外层可能是分组、内层才是真实页面。即使显示文字相同，也按不同菜单 ID、路由、组件和源码匹配结果建模；外层纯分组不可执行，内层页面与其他同级页面并列，并承载自己的 `formCode`、执行能力和操作节点。禁止为了视觉去重把真实页面合并到父分组。
- 同一真实页面的平面操作、嵌套操作和详情树必须使用同一个 owner 路径。用“解析后的源码身份 + 规范化运行路由 + 执行域”确定操作 owner；普通菜单中同一身份只挂一组操作，优先源码匹配明确且路径更深的真实页面。连续同名父子场景中，菜单层级全部保留，但操作和详情都挂到具有真实组件和 `source_file` 的内层页面；不得出现“按钮挂内层页面、详情挂外层分组”或反向错挂。同一组件对应不同运行路由时分别保留操作；不同详情权限节点即使复用组件和详情路由，也按各自 `funcCode/id` 执行域分别保留。兄弟页面保持接口给出的同级关系。
- 父 ID 详情树只按源码调用组件与运行时菜单组件的规范化路径前缀关联，不按中文标题猜测。组件标准化必须先统一大小写，再移除 `/srcEi/views/`、`src/views/` 等源码根；页面有已确认页签时，先用详情来源与页签内容组件的共同目录选择唯一、最深的页签 owner，再回退到页面 owner；无候选或同级最深候选并列时不挂载。页签必须先生成、再挂载父 ID 详情树。挂载路径为 `owner / 详情 / API children...`，使用 `owner.route + /detail` 并设置 `requires_business_id=True`；节点 ID 以 `detail:father:<fatherId>:` 隔离。
- 页面内页签不是权限菜单或详情树节点。只有同一入口源码能同时证明静态 `el-tab-pane` 的 `label`、固定 `name` 和对应的本地导入内容组件时，才生成 `页面 / 页签` 子模块；动态标签、缺少 `name`、未被激活分支引用、无法关联导入组件或仅展示的页签均不生成。页签继承父页面路由，但使用独立 `tab_label` 标记，不能伪造成按钮操作或详情模块。
- 父 ID 详情树挂到已识别的页面页签 owner 时，所有递归详情节点及其源代码操作节点必须继承该 owner 的 `tab_label`、`tab_value` 和 `tab_owner_component`。这些字段是执行前切换列表页签的导航上下文，不是仅供树界面展示的元数据；不可从详情标题或同名菜单反推。
- 从每个页面或详情入口自身的 `index.vue`/`list.vue` 提取静态 `el-button`/`button` 文本，去重后作为操作节点挂到对应的运行时中文模块或详情节点下；排除保存、确定、取消、关闭、提交等弹窗内部动作。不要把同目录 `Modify.vue`、弹窗或通用 `components/component` 内部按钮提升成列表页操作。操作节点继承页面路由、组件、`formCode` 和 `requires_business_id`，并通过独立操作测试入口执行。
- 当 `index.vue`/`list.vue` 的模板仅渲染一个显式 import 的本地 Vue 组件时，将其视为透明页面包装器，沿该唯一组件继续提取页面操作，并按绝对路径去重以防循环 import；模板包含布局、多个组件或其他页面内容时不得跟随，以免把普通子组件、弹窗和通用控件的按钮提升为页面操作。权限条件既可能写在按钮标签上，也可能写在其祖先容器上，必须把祖先 `$hasButton('code')` 关联到后代按钮后再与当前用户权限取交集。
- 运行时 `component` 与源码入口不能只做字符串严格相等。依次使用标准化组件路径、唯一的 `funcCode/formCode`、运行路由与源码一级目录的唯一别名候选解析；最佳候选并列时保持未匹配，禁止猜测后错挂操作。普通菜单和详情菜单必须共用同一解析器。
- 部署菜单可能使用历史 `/srcEi/views/...` 组件别名，而页面实体仍位于 `src/views/...`。当逻辑组件路径唯一时允许 `srcEi -> src` 单向兼容；不要反向兼容，也不要在存在同根候选或多个最佳候选时跨根猜测。组件关联失败会同时丢失 `formCode`、页面操作和对话框操作，诊断时先输出运行时 `component/path/funcCode` 与最终 `source_file`。
- 运行时组件显式包含 `src/views/` 或 `srcEi/views/` 时，候选源码必须来自相同源码根。禁止把部署的 `srcEi` 页面降级匹配到本地 `src` 页面，反之亦然；同根页面缺失时保留菜单和路由，但不生成猜测的 `formCode`、能力或操作按钮，并在启动器状态中统计源码不匹配页面。
- 源码根不匹配时把“页面平面按钮”和“新增对话框结构”分开处理：平面按钮不得跨根回退；为避免丢失已确认的新增详情分区，可只对 `srcEi → src` 启用结构回退，并且只保留带 `operation_path` 的嵌套新增操作。结构回退不能恢复或猜测查询、编辑、删除等平面按钮。
- 操作扫描除原生 `button`/`el-button` 外，还要审计项目封装的命令组件；例如 `PurvarExport title="导出"` 应产生“导出”操作。只纳入语义明确的命令组件，不把 `PurvarPrint` 弹窗本体、标题组件或普通输入组件当作按钮。
- 列表页通过 `componentPath` 或 `localComponent` 打开新增对话框时，可递归解析该对话框显式 import 的本地 `.vue` 组件，并把“分区标题 / 操作”建模为带 `operation_path` 的嵌套操作。`componentPath` 按当前 views 根解析，`localComponent: "Modify"` 严格相对当前入口目录解析为 `./Modify.vue`；保留 `srcEi`/`src` 来源族。采集分区内新增、删除、编辑、导入等所有语义明确的命令，排除保存、确定、取消、关闭、提交等对话框框架按钮；把引用限制在当前 view 源码树内，按绝对路径去重以防循环 import。
- 嵌套操作保留完整层级，例如 `模块 / 新增对话框 / 股东信息 / 新增`，执行时同时传递末级操作文字和 `operation_path`。不要把不同分区的同名“新增”压成一个扁平节点。
- 每次调整关联规则后做全量审计：统计源码入口总数、带操作入口数、操作总数，并重点检查“源码存在明确命令组件但操作数为 0”的页面。回归用例至少覆盖组件精确匹配、路由别名唯一匹配、别名候选冲突时不匹配、详情节点不被父路由误匹配。
- 新增类操作复用完整新增、保存和详情回读闭环；查询、重置、编辑和业务操作点击验证。删除、移除、清空等破坏性操作只验证可见入口，不自动点击或删除业务数据。
- 展开指示器必须依据渲染后的真实子节点判断；没有 `get_children()` 的叶子节点不显示箭头。不要依赖不同 ttk 主题含义不一致的内部状态位。
- 将父节点“模块层级”单元格作为展开/收起热区，避免只让细小箭头图形可点击；点击后仍保留行选择和父子级联高亮行为。
- 源码扫描失败或切换项目时清空旧树、选择和运行时状态，禁止混用上一个项目的数据。
- 可运行菜单节点带有运行时 `component`、但最终 `source_file` 为空时，启动器必须在浏览器启动前明确失败并报告组件路径和源码版本不匹配。禁止因 `supports_add=False` 将其降级为页面访问通过；重新选择正确源码分支并获取菜单后再执行。

## 诊断结论

- 显示技术目录名或“待获取路由”：源码扫描已完成，但尚未取得运行时菜单，不能判定扫描无效。
- FI 选择后仍出现 EI 菜单：检查 source root、view root、`VITE_APP_ID` 和已部署 URL 是否属于同一应用。
- 主菜单成功而详情为空：检查详情前缀发现结果、认证头复用和当前用户权限，不要立即假设数据库无数据。
- 详情树必须挂到发起该详情权限请求的真实业务页面，不挂到同名 `Layout` 分组。未知详情前缀选择 owner 时优先“有 `source_file` 且组件精确等于前缀”的页面，其次才是组件子路径和路由匹配；不得用 `len(path) == 1` 强制选择一级分组。连续同名父子场景中，详情路径应为“外层分组 / 内层页面 / 详情”。
- 详情模块看似不全：先分别统计详情接口原始节点、转换后的详情节点和界面叶子节点。原始响应缺失属于采集或权限问题；转换结果完整但界面不可见属于折叠或渲染问题，不要混为同一个缺陷。
- 详情父分组存在但子模块不可见：检查树节点的 `open` 状态和 `requires_business_id` 标记；详情分支必须全部展开，不能仅凭父节点存在就判定展示完整。
- 登录后仍拿不到菜单：保留网络日志，核对真正成功的菜单请求、重定向后的业务应用地址和 storage state。

## 验证

- Discover static father-ID detail trees from both `src/views` and `srcEi/views`, in stable source-root and source-path order. A detail route may pass `fatherId` through a computed route-query variable with a source-declared literal fallback; resolve that fallback only when it is explicit, then request the read-only tree. Attach the result only to the unique deepest page-tab component directory shared with the detail component. That tab must already be proven by its label, fixed name, local import, and active rendering branch in the Vue template. This preserves distinct before/after trees such as `projectManage/before` and `projectManage/after`; never copy one tree to a sibling tab or infer ownership from a title.
- Father-ID detail nodes are added after primary page actions. Run the same source-component action binding after those nodes are appended: retain only source-confirmed operations and apply the current-user button-permission filter. A node with no unique source-component match must remain operation-free rather than inheriting a sibling's actions.

## 源码按钮与用户权限

- 从页面自身的 `index.vue`/`list.vue` 提取静态按钮文字，并同时提取同一按钮标签上的 `$hasButton('code')`；一个按钮允许关联多个权限码，任一命中即可展示。
- 不要只保存按钮文字。把每个候选建模为静态操作记录，至少包含：显示名称、权限码集合、触发处理器或命令、作用域（工具栏/行操作/对话框分区）和来源组件。后续权限过滤、去重和执行目标解析都使用该记录。
- 操作入口不仅包括原生 `button`/`el-button`，还应审计 `el-link`、下拉菜单项、表格操作插槽和项目封装的命令组件；只纳入语义明确且能解析到稳定名称与触发命令的入口，不把普通导航链接和展示组件当操作。
- 将权限条件与业务显示条件分开解析。`$hasButton(...)` 决定当前用户是否拥有候选能力；行状态、流程状态、`disabled`、普通 `v-if` 等只标记该操作为条件性能力，不能因为权限命中就宣称它对所有记录可点击，也不能因当前列表没有满足条件的数据就删除该能力。
- 去重使用稳定语义键，优先采用“规范化权限码集合 + 触发处理器/命令 + 作用域”；缺少这些信息时才退回“规范化名称 + 作用域”。同一操作因响应式分支或重复模板出现多次时合并，名称相同但作用域或处理器不同的操作保持独立。
- 无 `$hasButton` 限制的查询、重置等页面通用按钮直接保留；有权限码的按钮只在当前用户按钮权限集合命中时保留。权限接口明确返回空集合时，所有受权限控制的按钮都不得展示。唯一例外是父 ID 详情树：组件已精确匹配源码、接口返回了非空菜单级权限码、但该详情组件的全部受控按钮均未被该集合覆盖时，保留该组件的源码动作作为待运行时验证的候选；一旦该组件任一权限码命中，仍严格过滤未命中动作。此回退不能用于普通菜单、空权限集合或源码关联不确定的详情节点；回归同时断言“完全未覆盖时保留”和“部分命中时仍严格过滤”。
- 核对单页结果时分别输出三组事实：源码候选的“文字 → 权限码”、当前用户与该模块相关的权限码、最终保留按钮。源码有但用户无权限的按钮必须过滤；用户有但源码无该按钮的权限码同样不得生成操作。
- 审查多行 `<el-button>` 时读取完整标签块或用解析器提取，不以 `rg` 的有限上下文、截图裁剪或首个匹配作为“源码没有按钮”的证据。截图只用于复核最终结果，不能替代源码候选和权限集合。
- 权限接口请求失败时才允许回退源码候选，并在状态或日志中说明未完成用户权限过滤。禁止通过逐页 DOM 扫描推断按钮权限，该方案慢、受页面数据和加载状态影响，也容易造成启动器长时间等待。
- 权限接口成功返回空集合与请求失败含义不同：空集合表示当前用户没有受控按钮权限，必须过滤全部带 `$hasButton` 的候选；请求失败才用缺失值表示未知并回退源码。不要用空列表同时表达这两种状态。
- 平面操作的唯一来源是当前运行菜单组件对应的 `index.vue`/`list.vue`。最终结果 = 源码无权限按钮 +（源码受控按钮 ∩ 当前用户 `_buttonCodes`）；嵌套操作继续来自源码对话框结构的 `operation_path`。
- 禁止使用页面 DOM 按钮快照、部署 Vite Chunk、按钮文字白名单或版本门禁切换其他采集源。即使输入载荷残留 `_visibleActions`、`_deployedActions` 或 `_actionDiscoveryMode`，菜单合并层也必须忽略。
- 运行时组件无法精确关联所选源码时，不生成猜测按钮并在启动前报告源码不匹配。由使用者保证所选源码对应部署版本。
- “源码按钮 + 当前用户权限”只能判断源码中受权限控制的候选按钮，不能覆盖源码版本差异、行数据状态、流程状态和额外业务条件。权限接口存在某权限码不代表按钮在所有页面状态下必定显示；发现权限名称与页面文字不同（例如源码“入库申请”、部署页“立项准备”）时，按版本不一致处理，不继续叠加别名猜测。
- `模块ID::action::<position>` 仅是本次树构建的展示/调度 ID，位置会随源码按钮增删和过滤结果变化。跨刷新、日志关联和重试使用“运行时菜单 ID + 规范化操作名 + `operation_path` + 权限码/处理器”作为稳定身份，禁止持久化或反向解析位置编号来决定点击哪个按钮。

## 对话框内子模块发现

- 菜单路由和 `index.vue`/`list.vue` 只能覆盖页面入口。对原入口及其透明包装组件分别发现对话框；入口通过 `componentPath` 或 `localComponent` 打开动态对话框时，继续解析该对话框，并沿其实际 `import` 递归读取被引用的本地 Vue 组件。`componentPath` 只接受直接字符串或同文件唯一的静态字符串 `const`，`localComponent` 保持相对入口目录解析；变量链、冲突声明和未引用文件不得猜测或扫描。
- 仅把同时具有稳定区块标题和明确命令按钮的区域识别为对话框子模块。例如独立的“股权结构 / 新增|删除”和“对外投资 / 新增|删除”均应采集；纯展示组件、通用控件、未被入口引用的组件不得采集。
- 把每个 `PurvarSubTitle` 或可识别的动态标题标记作为分区边界，当前分区只扫描到下一标题。区块名称可以来自静态 `title="..."`，也可以来自标题属性的稳定默认值；动态表达式无法解析出稳定中文标题时不生成该分区节点，但仍终止上一分区，防止后续按钮串入错误标题。
- `dialogTitle` 间接来自调用参数时，只关联静态对象中带明确 `add/edit/detail` 模式、且前缀能匹配真实页面操作的标题。同一唯一对话框组件被多个明确调用上下文复用时，按源码顺序分别保留“新增/编辑”等外层路径；存在多个对话框组件却无法证明标题归属时不得交叉组合。无法证实时保留单一通用对话框标题，不按模块名猜测。
- 为对话框操作保存完整操作链，例如 `新增 -> 股权结构 -> 新增`、`新增 -> 股权结构 -> 删除`。树路径按真实归属显示为 `模块 -> 外层操作 -> 对话框标题 -> 区块标题 -> 嵌套操作`，使嵌套按钮成为对应“新增/编辑”等外层操作的后代；运行时菜单合并不得固定截取末尾层级，而应按完整 `operation_path` 保留外层操作。这样可避免不同分区的同名操作合并、与外层操作并列或执行时误点外层按钮。
- 嵌套操作继承其外层按钮的权限码，并与外层操作使用同一用户权限结果过滤；禁止在外层“新增/编辑”无权限时单独显示或调度其对话框后代。
- 对所有模块统一解析对话框标题与页面操作的对应关系，例如“新增资源池企业”归属“新增”、“编辑客户”归属“编辑”；禁止把嵌套链的外层操作写死为“新增”或按模块名维护特例。将对话框嵌套操作紧跟在其 `operation_path` 指向的外层操作之后，保持源码/UI 顺序；界面树与执行目标必须复用同一有序条目流，禁止先追加全部平面操作、再把嵌套操作统一放到末尾。无法可靠匹配外层操作时不得猜测归属或生成错误嵌套操作。
- 不使用运行时页面 DOM 按钮快照或部署 Chunk 覆盖源码操作。页面尚未打开对话框、当前页没有满足行状态的数据、异步配置未加载时，DOM 快照都不是完整能力清单；平面和对话框操作都从对应源码结构生成。
- 回归用例至少覆盖：动态 `componentPath`、相对入口目录的 `localComponent`、`srcEi` 来源保持、两层以上被引用组件、同一对话框多个同名操作、未引用组件不采集、平面操作更新不覆盖对话框操作链，以及工具栏/行操作/下拉命令的静态识别与语义去重。
