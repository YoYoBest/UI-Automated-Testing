# 冒烟测试数据策略

## 事实来源

- `data/common_data.json`：全局语义映射、公共候选池和合法生成约束。
- `data/collected_data.json`：自动采集缓存，不手工维护。
- `data/overrides.json`：按 `formCode` 集中维护少量特殊覆盖。
- `data/collection_sources.json`：采集接口和允许字段白名单。
- `data/unique_constraints.json`：按 `formCode` 声明组合唯一字段、可安全变化的修复字段和后端重复提示特征。
- `src/ei_ui_smoke/data_pool.py`：公共池加载、语义识别和约束生成器。
- `src/ei_ui_smoke/data_strategy.py`：probe/stable 取值策略。
- `src/ei_ui_smoke/collector.py`：列表、详情采集和原子写入。

不要为每个页面创建完整业务数据文件，也不要把测试值写进 Skill。

## 模式选择

- `probe`：新页面快速探测。按字段代码、名称、类型和公共约束自动生成，不要求提前准备页面数据。
- `stable`：版本日常回归。优先使用已验证、可复现的公共数据和采集数据。
- `standard`：标准自动化。使用新生成的合法数据执行保存、接口状态和回显闭环，并严格要求当前可编辑字段全部完成填写；普通模式中仅记录的可选字段无数据或交互失败在该模式下必须阻断。
- 图形启动器通过“快速探测/稳定冒烟/标准自动化”单选切换。企查查字段继续由通用字段驱动识别，不保留独立的企查查执行模式。
- pytest 通过 `--data-mode probe`、`--data-mode stable` 或 `--data-mode standard` 切换；未指定时读取 `EI_DATA_MODE`，再回退到默认 `probe`。

## 取值优先级

稳定模式严格按以下顺序取值：

1. `overrides.json` 中当前 `formCode` 的特殊字段覆盖。
2. `collected_data.json` 中当前表单采集到的合法值。
3. `common_data.json` 的公共候选池或受约束生成器。
4. 字段配置的 `defaultValue` 或 `propsJson.defaultValue`。
5. 按字段类型生成的确定性兜底值。
6. 对下拉、选人、组织、树和远程搜索组件，从页面真实接口加载的当前可见候选项中选择。

probe 模式不读取页面专属业务值，但仍必须遵守公共合法规则，并从真实下拉候选中选择。

单选、下拉等选择类字段必须按选项的业务 value 或规范化显示文字匹配，禁止用 DOM 顺序、`first`/`last` 推断业务含义。stable 模式优先使用 override、采集值或配置值对应的明确语义选项；probe 模式可以选择确定性的合法候选，但同一输入必须稳定复现。页面已有 checked/selected/default 值时一律保留，只有可唯一映射到该字段的校验错误才允许修复；诊断和回显比较同时记录实际显示值及可取得的底层代码。

## 生成规则

- 根据字段语义生成手机号、统一社会信用代码、金额、企业名称等值，而不是对所有文本框使用同一种字符串。
- 手机号使用合法号段；信用代码生成校验位；金额限制在配置区间。
- 同一 `run_id` 和字段输入应产生可复现结果，便于定位失败。
- 唯一名称附带运行标识，避免与历史记录冲突并便于列表回查。
- 唯一性可能由多个字段共同决定。源码、接口提示或历史响应确认组合唯一键后，在 `unique_constraints.json` 声明完整 `fieldCodes`、`repairField`、受保护时可用的 `alternateRepairFields`、列表端点、记录路径、码值/显示名别名和 `messageIncludes`；例如“板块 + 年度”中金额变化不能避免重复。创建前刷新并捕获当前浏览器登录态下的真实列表请求，按原请求逐页读取全部占用组合并核对总数；先原子预留当前组合，当前组合未占用时保持所有已有值，只有已占用或已被同进程预留时才修改未受保护的修复字段。分页证据不完整、记录缺键、所有真实选择项均占用或全部修复字段受保护时安全失败，禁止猜值、盲试或覆盖 Excel 目标字段。
- 唯一修复必须保持字段类型：年份产生四位年份序列，日期/时间按单位偏移，数字按 `step/precision/min/max` 递增，只有文本才追加运行后缀。禁止把 `2026` 修成 `2026_run_1`。复合键预留按部署页面 scope 隔离并跨策略实例共享；码值和显示名作为同一字段的别名参与冲突判断。UI 写入或保存失败必须释放待定预留，业务保存成功后才提交该预留，避免失败事务造成进程内假占用。
- 启动器为一次批量执行生成 `EI_AUTOMATION_RUN_ID`，并为每个 pytest 子命令追加 `EI_AUTOMATION_TARGET_SEQUENCE`；未显式传入运行标识的数据策略必须组合这两个值，使同一轮不同目标的数据仍可区分且可复现。
- 通用值工厂不得为选择控件生成 `AUTO_*` 等伪文本：单选、下拉返回空字符串哨兵，多选、复选返回空列表，由运行时交互层保留页面已有值或从控件真实候选项中选择。
- 业务合法性无法由通用规则保证时，只在 `overrides.json` 增加最小覆盖，不复制整张表单。

## 校验驱动修复

字段已定位但页面或保存接口提示值不合法时，执行受控修复：收集字段级提示 -> 映射稳定字段码/标签 -> 解析确定约束 -> 只重填对应字段 -> 再校验或保存。默认最多三轮，并把旧值、提示、解析约束、新值、轮次、提示来源和结果写入 `validationRepairs`。

把校验修复实现为结构化约束管道，不为完整提示句子逐条编写分支。先读取控件和源码的 `type/inputmode/min/max/step/precision/minlength/maxlength/pattern`，再把提示归类为必填、数值、整数、正负、长度、格式或唯一性，最后由统一生成器按组合约束产值。提示措辞变化但约束类别相同不得要求新增页面专属规则；结构化上下界冲突、pattern 无法生成匹配值或错误属于权限/流程/系统/网络时停止修复。

约束可信度依次为 DOM `required/maxlength/min/max/step/pattern`、Vue/Element 字段错误、保存接口明确字段提示、公共数据池。当前可自动处理必填文本、邮箱、11 位手机号、字符长度、数值上下界、重复文本、年份、日期和数字；选择、组织、人员和树控件仍从真实候选项选择，不根据错误文本伪造值。

后端明确字段提示覆盖通用生成值时，只重填命中的字段并重新读取 DOM；禁止重新生成或覆盖其他已成功字段。每轮把旧值、提示来源、解析约束、新值、轮次和结果追加到 `validationRepairs`，便于判断修复是否真正生效。

只有提示能映射到一个具体字段且能解析为确定约束时才重试。权限不足、流程状态、系统异常、网络错误、模糊业务错误和无法唯一映射字段的提示必须停止并保留诊断。保存请求没有明确业务失败时不得盲目重复点击，防止重复新增；只有客户端校验未发请求，或接口明确返回业务失败时才允许修复后重试。

无字段名的重复提示只有在表单中能确定唯一候选时才修复：优先使用 `unique_constraints.json` 中已确认的组合约束和修复字段；否则使用唯一远程企业字段并从新的真实搜索结果选择候选，或对唯一的名称、账号、编码字段生成唯一值。存在多个候选且没有声明约束时停止自动修复，不猜测。

创建数据策略时必须传真实业务 `formCode`，不得传运行时菜单 ID、`::action::` 动作 ID 或模块显示名称；否则 stable 覆盖、采集数据和组合唯一约束都会静默匹配失败。

新增提示解析规则时，至少覆盖“合法提示生成符合值”和“权限/流程提示不触发修复”两类测试。具体实现集中在 `src/ei_ui_smoke/validation_repair.py`，禁止在页面驱动中散落中文提示判断。

保存接口或前端契约明确要求用户填写业务主键时，使用精确字段语义生成可复现的纯数字标识。例如 `itemId`/标签 `ID` 可映射为 `businessIdentifier`；不要用宽泛的 `id` 子串规则影响 `orgId`、`fundId` 等应由下拉或后端产生的字段。系统异常、HTTP 500 或模糊错误本身不能触发猜测修复，必须先从字段契约、真实响应或源码确认约束。

## 自动采集

1. 只从已配置的列表和详情接口读取既有测试记录。
2. 仅保存 `allowedFields` 白名单中的字段，禁止采集密码、Token、Cookie、个人敏感信息或完整响应。
3. 记录来源业务 ID 和采集时间，去重后通过临时文件原子更新 `collected_data.json`。
4. 冒烟执行只读采集缓存，不在测试过程中边采集边修改数据来源。
5. 采集结果仍不满足新页面时，补充公共语义规则或最小覆盖，不建立页面完整副本。

## 字段语义识别

- 语义映射同时检查稳定业务字段代码和可读标签，优先信任业务字段代码。禁止使用 `el-id-*`、占位文本或 DOM 数组位置推断邮箱、手机号、金额等语义。
- 源码字段与运行时 DOM 必须先按业务代码对齐，再把代码和标签交给 `semantic_for()`。若按下标错配，即使生成器本身正确，也会让邮箱字段得到普通文本值。
- 为新语义或别名补充 `data/common_data.json` 的 `fieldMappings`，并增加覆盖字段代码和中文标签的策略测试；不要在页面驱动中硬编码邮箱字符串等数据。
- 邮箱值必须由 `email` 生成器产生并满足有效邮箱格式；运行标识用于避免重复，但域名、长度和唯一性仍以公共数据配置为准。

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_data_strategy.py tests\test_collector.py tests\test_case_data.py tests\test_values.py -q
```

验证模式切换时记录最终 `data_mode` 和 `run_id`，但不要把凭证或采集到的敏感值写进 Allure 环境信息。
