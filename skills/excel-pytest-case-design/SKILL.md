# Excel Pytest 用例设计

## 核心原则

- 区分“人工可执行”与“机器可执行”。自然语言步骤清晰不等于 pytest 能解析。
- 保留人工用例页；新建 `<功能>_自动化` 页，只迁移结构稳定、可数据驱动的用例。
- Excel 保存测试语义和数据，Python 保存定位、控件交互和断言实现。不要在 Excel 中维护完整 XPath/CSS 或 Python 表达式。
- 一行只验证一个核心规则；每个输入、操作和预期必须唯一且可判断。
- 同一输入和提交动作下，“操作被阻止”与“提示文案正确”属于同一校验结果，不要复制一行；将精确提示写入结构化 `expected_value`，执行器必须比较实际提示，不能只判断任意错误提示存在。只有触发条件、提示时机或匹配策略不同才拆成独立用例。
- 不要求 `field_key` 与数据库列、接口参数或中文标签同名，但必须与 Python 配置中的键严格匹配，并能唯一映射到真实控件。
- 先填一份合法基准表单，再只修改当前目标字段，避免一个失败同时受多个字段影响。

## 工作流

1. 读取工作簿实际表头、样例行、数据验证和合并区域；不要只根据截图判断。
2. 判断目标是人工执行、pytest 参数化，还是两者兼顾。
3. 对人工用例执行规范化：补齐具体数据、编号步骤、唯一预期、优先级和执行状态；清除 `XXX`、`符合需求`、`正常` 等不可判定文本。
4. 对自动化用例执行结构化：使用固定机器列和枚举，不解析自然语言步骤。
5. 只迁移简单字段规则；复杂联动、富文本、上传下载、防重复提交和跨页面流程默认写成独立 pytest。
6. 建立 `module_key + field_key -> Page Object/字段配置` 映射，并在收集用例时提前校验未知键、重复 ID、非法枚举和空断言。
7. 运行时 DOM 发现晚于 pytest 参数收集时，使用两阶段流程：先打开页面发现字段并写入清单，再在下一次 pytest 收集时读取清单并绑定 Excel 规则。不要尝试从 fixture 动态增加参数。
8. 用 `case_id` 生成 pytest `ids`；禁用或尚未确认的行不进入参数集合。
9. 用至少一个正常、一个异常、一个边界案例验证 Excel 类型转换、特殊值解析、页面定位和错误断言闭环。

## 判定是否可直接参数化

只有同时满足以下条件，才判断页签符合 pytest 参数化标准：

- 具有唯一 `case_id` 和显式 `enabled`。
- 具有稳定的 `module_key`、`field_key`。
- `operation`、`submit_action`、`expected_type` 均来自固定枚举。
- `input_value` 是实际值或受支持的确定性表达，不是“49 个字符”“构造边界值”等人工指令。
- `expected_value` 是唯一可观察结果，不包含“或者”“按需求”等分支。
- `field_key` 能在代码配置中唯一映射；未知键在 pytest 收集阶段失败。
- 依赖规则已确认；`待确认` 行默认不执行。

只具备“前置条件、测试数据、操作步骤、预期结果”的页签属于人工可执行用例，不得宣称已能直接驱动 pytest。

## 数据边界

- 使用 `__EMPTY__` 表示清空，避免与 Excel 空单元格混淆。
- 仅在接口测试需要时使用 `__NULL__` 和 `__MISSING__`，分别表示 JSON `null` 和不传字段。
- 长文本使用确定性表达，例如 `__REPEAT__:a:51`，由加载器生成实际字符串；禁止执行任意 Python 代码。
- 手机号、证件号、编码和前导零值按文本读取；数值、百分比和日期按真实类型读取并显式转换。
- Excel 空单元格不能隐式代表清空、空字符串或字段缺失。

## 与现有 Skills 协作

- 实际编辑 `.xlsx` 时同时遵循可用的 spreadsheet artifact skill，并保留原工作簿样式和非目标页签。
- 合法测试值、稳定模式和公共数据池遵循 `skills/smoke-test-data-strategy/SKILL.md`。
- 页面字段交互、新增闭环和保存后回读遵循 `skills/generic-module-crud-smoke/SKILL.md`。
- pytest 执行、浏览器会话和 Allure 编排遵循 `skills/ui-smoke-test/SKILL.md`。

## 详细规范

创建、修改或审阅自动化页签时，读取 [references/parameterization-standard.md](references/parameterization-standard.md)，使用其中的列定义、枚举、映射和 pytest 骨架。

## 验证清单

- `case_id` 非空且全表唯一。
- `enabled` 仅为 `Y/N`。
- 所有机器枚举值合法。
- 启用行的 `module_key`、`field_key`、`operation`、`expected_type` 完整。
- 启用行不存在 `XXX`、`按需求`、`正常`、`或者` 等不可执行描述。
- 每个 `field_key` 均能在模块字段配置中解析。
- 参数 `ids` 包含模块和用例 ID，避免 Allure 历史记录合并。
- Excel 配置错误与被测系统断言失败分开报告。
- 参数化测试之外的复杂场景仍有独立 pytest 覆盖。

## 多页签执行配置

- 不要把自动化规则页签写死在加载器内部。先从 `xl/workbook.xml` 按工作簿顺序读取页签名称，再让用户从带复选项的下拉菜单中显式选择一个或多个页签。
- Excel 尚未选择时，让文件选择器默认进入项目约定的公共用例目录；输入框仍保存具体工作簿路径，不要用目录路径冒充可执行 Excel。已有文件时回到其父目录并预选原文件，项目约定目录不存在时再回退项目根目录。
- 文件路径变化后立即刷新页签列表；按工作簿顺序仅保留用户显式选择且仍有效的页签。首次加载不默认勾选任何页签。
- 执行前校验工作簿存在且 XLSX 结构可读。页签为空不是配置错误，语义为按工作簿顺序执行全部页签；用例 ID 为空同样表示所覆盖页签中的全部用例。显式选择仍必须存在，配置错误必须在启动浏览器前失败。
- 每个选中页签生成独立 pytest 批次，并通过现有单值 CLI 参数和环境变量逐批传递；不要把多个页签拼成一个参数交给只接受单页签的加载器。字段发现与字段验证必须在同一页签内相邻执行，不同页签的日志名称必须可区分，避免覆盖。
- 只读取元数据时优先使用 OOXML 和标准库，不为枚举页签引入完整 Excel 依赖。
